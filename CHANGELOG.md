# Changelog

All notable changes to this project are documented here.
Format: Keep a Changelog. Versioning: Semantic Versioning.

## [Unreleased]

### Added

- Troubleshooting: the configuration errors fleetlint stops with, their exact messages and what to change.
- The CLI reference, generated by `fleetlint docs`: every command and flag, exit codes and environment variables.
- `make lint` loads every configuration and catalog example (`scripts/check-examples.py`) and checks the rule catalog's ids, severity, tiers, preset, kind and totals against the generated rule pages (`scripts/check-rule-catalog.py`).
- The documentation site: getting started, the baseline, stack profiles, the slop catalog, the rule catalog and generated rule reference, configuration, organisations, fleet mode, writing rules, the CEL reference, integrations, a comparison with related tools, and the demo page. Moved here from the fleetlint repository.

### Changed

- A review of every page against fleetlint 0.10.2 and catalog 0.7.0, for fleetlint 0.11 (catalog 0.8):
  - Examples that did not load are fixed; tier inference, forge detection, OCI and git pins, and `exceptions: false` (which now also forbids disabling) are described as the code does them.
  - Getting started keeps to the happy path: exit codes, tiers and forge tokens as tables.
  - Writing rules runs from a first rule to library-only parts, with "Testing a rule", the load errors and `foreach`. Organisations follows an administrator's path, with one end-to-end example. Fleet mode has one "Forges and tokens" section, exit codes and every output file.
  - The rule catalog marks all 22 capabilities and its check summaries match the rules; stack profiles name only tools the rules accept and link the capability matrix; the baseline explains how the tier is inferred and what runs at tier 3; the slop catalog matches what its rules read.
  - Integrations has input tables for the action and the GitLab component, and pins `version` and the `$schema` URLs.
- For fleetlint 0.6 (catalog 0.3): catalogs apply in written order and carry free labels (`metadata.label`) instead of the fixed layers; `fleetlint hierarchy` and the `catalogs` list in every report; artifacts as catalog data and the release capabilities keyed by artifact, with an artifact matrix on the capabilities page; fleet files that include fleet files and nested groups; `facts.artifacts`. The generated rule pages name catalog v0.3.0.
