# fleetlint documentation

The source of [fleetlint.org](https://fleetlint.org): what [fleetlint](https://github.com/fleetlint/fleetlint) checks and why, how to configure it, how to roll it out across an organisation, and the reference for every rule.

## Quickstart

```sh
make serve     # preview at http://localhost:1313
make check     # generated pages current, site builds without warnings, every link resolves
```

The toolchain is pinned in `mise.toml`: Hugo, Node (for the search index), Python (for the link check), Go and gitleaks. With [mise](https://mise.jdx.dev), `mise install` provides all of them; without it, install those versions yourself. `make tools` then installs fleetlint. The workflows read the same file.

## Layout

| Path | Contents |
|---|---|
| `content/*.md` | the pages, written by hand; links between them are relative `.md` paths, so they also work when read here |
| `content/rules/`, `content/cel-reference.md` | generated by `fleetlint docs` from the catalog built into fleetlint; do not edit. Each page names the catalog version at its foot. |
| `layouts/`, `assets/style.css` | the site: one stylesheet, no JavaScript except on the search page |
| `hugo.toml` | configuration and the navigation |
| `scripts/check-links.py` | checks every link and anchor in the built site |

## Changing a page

Edit the Markdown under `content/`. A link to a page that does not exist fails the build; a link to an anchor that does not exist fails `make test`.

## After a fleetlint or catalog release

```sh
make tools     # installs the fleetlint version named in the Makefile
make gen       # regenerates the rule pages and the CEL reference
make check
```

`make lint` fails when the generated pages differ from what the installed fleetlint would write, so the site cannot silently describe other rules than the release it documents.

## Dependency updates

Renovate reads `mise.toml` for the toolchain, the pinned actions in the workflows, the hook revisions in `.pre-commit-config.yaml`, and the Pagefind version in the Makefile through its `# renovate:` comment.

## Publishing

A push to `main` (and a nightly run, for the demo) builds the complete site (`.gitea/workflows/deploy.yml`): Hugo output, the fleet report under `demo/report/`, the search index. A shared deploy workflow receives it as the `site` artifact and publishes it to fleetlint.org. The root documents the latest release.

Each release's docs are frozen under `/vX.Y/` (the minor of `FLEETLINT_VERSION`, see `make snapshot`). Releases are manual: after the version bump has landed, run the deploy workflow on `main` with `release` checked. It stores the snapshot in the Gitea package registry as `fleetlint-docs` (`scripts/snapshots.sh`; a patch release replaces its minor's snapshot), and every deploy adds the stored snapshots and the `versions.json` for the version switcher. Old versions show a banner and point their canonical link at the root. The deploy needs a `PACKAGES_TOKEN` secret with `read:package` and `write:package`.
