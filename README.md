# fleetlint documentation

The source of [fleetlint.org](https://fleetlint.org): what [fleetlint](https://github.com/fleetlint/fleetlint) checks and why, how to configure it, how to roll it out across an organisation, and the reference for every rule.

## Quickstart

```sh
make serve     # preview at http://localhost:1313
make check     # generated pages current, site builds without warnings, every link resolves
```

Needs [Hugo](https://gohugo.io) (extended), Python 3 for the link check, `gitleaks`, and `fleetlint` on the PATH. `make search` adds the search index and needs Node.

## Layout

| Path | Contents |
|---|---|
| `content/*.md` | the pages, written by hand; links between them are relative `.md` paths, so they also work when read here |
| `content/rules/`, `content/cel-reference.md` | generated by `fleetlint docs` from the catalog built into fleetlint; do not edit. Each page names the catalog version at its foot. |
| `layouts/`, `assets/style.css` | the site: one stylesheet, no JavaScript except on the search page |
| `hugo.toml` | configuration and the navigation |
| `scripts/check-links.py` | checks every link and anchor in the built site |

## Changing a page

Edit the Markdown under `content/`. A link to a page that does not exist fails the build; a link to an anchor that does not exist fails `make test`.

## After a fleetlint or catalog release

```sh
make tools     # installs the fleetlint version named in the Makefile
make gen       # regenerates the rule pages and the CEL reference
make check
```

`make lint` fails when the generated pages differ from what the installed fleetlint would write, so the site cannot silently describe other rules than the release it documents.

## Publishing

A push to `main` builds the site and publishes it to GitHub Pages (`.github/workflows/pages.yml`). The site documents the latest release only.
