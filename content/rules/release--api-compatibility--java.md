## Requirement

A library published with maven-publish or Maven deploy runs japicmp or revapi against the previous release.

## Why

A breaking change in a minor release is found by every user at once; the check finds it before the tag.

## Applies when

```cel
grep("**/build.gradle*", "maven-publish").size() > 0 || grep("**/pom.xml", "<distributionManagement>").size() > 0
```

## Fix

Add japicmp-maven-plugin (or me.champeau.gradle.japicmp) comparing against the previous release version.

Agent instruction: Add the stack's API compatibility tool to the release workflow, comparing against the latest tag; on a breaking change bump the major version instead of silencing the tool.

A finding of this rule points at the file `(["pom.xml", "build.gradle.kts", "build.gradle"].filter(f, file(f)) + ["pom.xml"])[0]` yields.
