# ci/sast

Code is scanned by a SAST tool

A capability: each stack checks it with its own tools. Implemented for [any](ci--sast--any.md), [php](ci--sast--php.md), [ruby](ci--sast--ruby.md).

Combine: `all`. Every implementation that runs must pass: each stack in the repository meets the requirement with its own tools.

## Requirement

A static application security test runs in CI or the task runner: a stack-neutral scanner (CodeQL, Semgrep or Opengrep, GitLab SAST, SonarQube) or the stack's own taint analysis (Brakeman for Rails, Psalm's taint analysis for PHP). Linters with security rules count under the lint rules, not here. CodeQL default setup, which leaves no file in the repository, and other scanners are declared with `accept:`.

## Why

SAST follows data from input to dangerous sinks across files, which per-file linters do not; on GitHub CodeQL is free for public repositories.

## Fix

Add a CodeQL workflow (GitHub advanced setup), include the GitLab SAST component, or add a Semgrep step to CI; with CodeQL default setup, declare it with `accept:`.

Agent instruction: Add a CodeQL workflow (github/codeql-action init/analyze, pinned) for the repository's languages, or on GitLab include `components/sast`; run it on pull requests and weekly.
