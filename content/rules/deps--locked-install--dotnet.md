# deps/locked-install/dotnet

Installs use the lockfile strictly

Implements [deps/locked-install](deps--locked-install.md) for dotnet.

## Requirement

Where packages.lock.json files exist, restore runs in locked mode: `--locked-mode` on `dotnet restore` in a recipe or CI step, or `RestoreLockedMode` set to true (typically conditioned on CI) in a project or Directory.Build.props.

## Why

An install that quietly re-resolves builds and tests something other than what the lockfile in git says, and the drift shows up only in production.

## Applies when

```cel
exists("**/packages.lock.json")
```

## Check

```cel
(taskrunner.recipes.filter(t, !t.matches(r'(?i)update|upgrade|lock|bump|renovate')).map(t, taskrunner.recipes[t]).flatten()
    + workflows().map(w, steps(w).map(s, s.run.split("\n")).flatten()).flatten())
    .filter(l, !l.matches(params.noise)).exists(l, l.matches(r'\bdotnet\s+(restore|build|test|publish)\b[^;&|]*--locked-mode\b'))
|| (glob("**/*.csproj") + glob("**/*.fsproj") + glob("**/Directory.Build.props")).exists(f, text(f).matches(r'(?i)<RestoreLockedMode[^>]*>\s*true'))
```

## Parameters

- `noise`: `^\s*[@+-]*\s*(\{\{[^}]*\}\}\s*|\$[({][A-Za-z_]+[)}]\s*)?(#|//|echo\b|printf\b)`

## Fix

Add `<RestoreLockedMode Condition="'$(CI)' == 'true'">true</RestoreLockedMode>` to Directory.Build.props.

Agent instruction: Switch the CI and task-runner installs to the package manager's locked mode; if that fails, regenerate the lockfile in a separate commit rather than relaxing the install.
