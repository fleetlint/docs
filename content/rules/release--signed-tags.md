# release/signed-tags

Release tags are signed

## Requirement

The newest `params.recent` version tags (semantic versions, with the component prefixes release/semver-tags accepts) are annotated tags with a PGP, SSH or X.509 signature (`git tag -s`). Tags created through a forge's release page are lightweight and fail; create the tag locally and push it, then publish the release from it.

## Why

A signed tag ties the released commit to a maintainer's key; the release pipeline then builds from something that can be verified, not just from a name.

## Parameters

- `recent`: `3`

## Fix

Set `git config tag.gpgsign true` (and `gpg.format ssh` with your SSH key) so every tag is signed; recreate unsigned release tags only if nothing depends on them.

Agent instruction: Tell the user which tags are unsigned and how to configure tag.gpgsign; do not delete or move tags.
