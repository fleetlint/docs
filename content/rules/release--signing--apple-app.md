# release/signing/apple-app

Release artifacts are signed

Implements [release/signing](release--signing.md) for the `apple-app` artifact: it runs when the release publishes one (see [artifacts](capabilities.md#artifacts)).

## Requirement

The build is code-signed with a Developer ID or distribution identity on export (xcodebuild -exportArchive with a signing identity, codesign, fastlane gym/match, `flutter build ipa --export-options-plist`); a macOS download is notarized and stapled (`notarytool submit`, `stapler`).

## Why

Checksums prove integrity; only a signature proves who built it.

## Capability applies when

```cel
release.exists || repo.artifacts.size() > 0
```

## Fix

Export with a signing identity (`xcodebuild -exportArchive -exportOptionsPlist` with the distribution certificate from CI secrets, or fastlane match + gym); for a macOS download add `notarytool submit --wait` and `stapler staple`.

Agent instruction: Use the artifact's own signing format when it has one. Otherwise add sigstore/cosign-installer and a signing step after the artifacts are built. Files: `cosign sign-blob --yes --bundle checksums.txt.sigstore.json checksums.txt` and upload the bundle. Container image: `cosign sign --yes <image>@<digest>` using the digest output of the build step, with `id-token: write` on the job.

A finding of this rule points at the file `artifact.workflows.size() > 0 ? artifact.workflows[0] : ".github/workflows/release.yml"` yields.
