# deps/license-check

Dependency licenses are checked against an allowlist

A capability: each stack checks it with its own tools. Implemented for [any](deps--license-check--any.md), [dotnet](deps--license-check--dotnet.md), [go](deps--license-check--go.md), [hugo](deps--license-check--hugo.md), [java](deps--license-check--java.md), [kotlin](deps--license-check--kotlin.md), [node](deps--license-check--node.md), [php](deps--license-check--php.md), [python](deps--license-check--python.md), [ruby](deps--license-check--ruby.md), [rust](deps--license-check--rust.md).

Combine: `all`. Every implementation that runs must pass: each stack in the repository meets the requirement with its own tools.

## Requirement

A task-runner recipe or a CI step checks dependency licenses against an allowlist with the stack's tool or a stack-neutral one (osv-scanner with license scanning, trivy's license scanner, ScanCode, FOSSA, ORT, GitHub dependency review with a license list). Applies at tier 1. Comments, `echo` lines and lines that only install the tool do not count. For a workspace member the repository's CI and the Makefile, justfile or Taskfile of a parent directory count as well. Another checker is added with `accept:`.

## Why

A dependency under an incompatible license is found cheaply before it is merged and expensively after a release.

## Fix

Add the stack's license checker with an allowlist to the `audit` target (see https://fleetlint.org/stacks/).

Agent instruction: Add the stack's license checker to the audit target with an allowlist compatible with the repository's own license; report dependencies outside it instead of widening the list.
