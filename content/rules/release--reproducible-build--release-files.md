# release/reproducible-build/release-files

Release builds are reproducible

Implements [release/reproducible-build](release--reproducible-build.md) for the `release-files` artifact: it runs when the release publishes one (see [artifacts](capabilities.md#artifacts)).

## Requirement

The binaries and archives are built without local paths or build-time stamps: Go with `-trimpath` (in .goreleaser.yaml together with `mod_timestamp`, or in the `go build` of the task runner or the publishing workflow); Rust with `cargo build --release --locked` and `--remap-path-prefix`; .NET with `ContinuousIntegrationBuild`; or `SOURCE_DATE_EPOCH` is set for the release build, in the workflow that publishes the files or the task runner.

## Why

When anyone can rebuild a release bit for bit from the tag, a tampered artifact or a compromised build machine shows up as a mismatch.

## Fix

Go: add `flags: [-trimpath]` and `mod_timestamp: "{{ .CommitTimestamp }}"` to the goreleaser builds. Rust: build with `--locked` and `RUSTFLAGS="--remap-path-prefix=$PWD=."`. .NET: set `ContinuousIntegrationBuild` in Directory.Build.props. Else export SOURCE_DATE_EPOCH from the commit time.

Agent instruction: Add the stack's reproducibility settings to the release build and derive SOURCE_DATE_EPOCH from `git log -1 --format=%ct`; do not change what is built.
