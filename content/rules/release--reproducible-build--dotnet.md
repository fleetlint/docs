# release/reproducible-build/dotnet

Release builds are reproducible

Implements [release/reproducible-build](release--reproducible-build.md) for dotnet.

## Requirement

`ContinuousIntegrationBuild` is true for CI builds (in a project or Directory.Build.props, or `-p:ContinuousIntegrationBuild=true` in the release workflow), which maps source paths away; deterministic compilation is the SDK default. Or SOURCE_DATE_EPOCH is set for the release build.

## Why

When anyone can rebuild a release bit for bit from the tag, a tampered artifact or a compromised build machine shows up as a mismatch.

## Capability applies when

```cel
release.exists
```

## Fix

Add `<ContinuousIntegrationBuild Condition="'$(CI)' == 'true'">true</ContinuousIntegrationBuild>` to Directory.Build.props.

Agent instruction: Add the stack's reproducibility settings to the release build and derive SOURCE_DATE_EPOCH from `git log -1 --format=%ct`; do not change what is built.
