# slop/non-conventional-commits

Commit subjects in the history follow Conventional Commits

## Requirement

Commit subjects in the recent history (`params.commits`, default 200) have the form `type(scope): subject`. Merge commits, git's own `Revert "..."` subjects and the root commit are exempt. `hooks/conventional-commits` checks that a hook prevents new ones; this rule reads what is already committed.

## Why

The changelog and the next version number are computed from the subjects.

## Applies when

```cel
repo.has_git
```

## Check

For each `item` in:

```cel
commits(params.commits)
```

```cel
item.subject.matches(r'^(feat|fix|refactor|perf|test|docs|build|chore|revert|ci|style)(\([^)]+\))?!?: ') || item.subject.startsWith("Merge ") || item.subject.startsWith("Revert \"") || item.root
```

## Parameters

- `commits`: `200`

## Fix

Install the commit-msg hook so new commits are checked.

Agent instruction: Use Conventional Commits for new commits. Do not rewrite pushed history without the user's decision.

See: <https://fleetlint.org/baseline/#slop>, <https://fleetlint.org/slop/#commits-and-history>
