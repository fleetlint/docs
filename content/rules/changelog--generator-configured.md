# changelog/generator-configured

Changelog generation is configured

A capability: each stack checks it with its own tools. Implemented for [any](changelog--generator-configured--any.md), [node](changelog--generator-configured--node.md), [python](changelog--generator-configured--python.md), [rust](changelog--generator-configured--rust.md).

Combine: `any`. One implementation passing is enough: this belongs to the repository, not to each stack, so the stack that does it decides and the others pass with it.

## Requirement

The changelog is generated from the commit history, then edited: a stack-neutral generator (git-cliff, GoReleaser, release-please, cocogitto, semantic-release, commitizen) or the stack's own (changesets for npm, towncrier for Python), configured in its own file or in the manifest.

## Why

Hand-written changelogs drift from the commits; generated ones can be trusted and edited.
