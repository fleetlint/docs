# repo/lockfile-committed/dotnet

Dependency lockfile is committed

## Requirement

packages.lock.json is tracked (`RestorePackagesWithLockFile`) when a project references NuGet packages.

## Why

Builds are reproducible only when dependency versions are pinned in git.

## Check

```cel
tracked().exists(f, f == "packages.lock.json" || f.endsWith("/packages.lock.json")) || !(glob("**/*.csproj") + glob("**/*.fsproj") + glob("**/Directory.Packages.props")).exists(f, text(f).contains("PackageReference") || text(f).contains("PackageVersion"))
```

## Fix

Set `<RestorePackagesWithLockFile>true</RestorePackagesWithLockFile>` in Directory.Build.props, run `dotnet restore` and commit the packages.lock.json files.

Agent instruction: Run the package manager to produce the lockfile, remove any .gitignore entry for it, and commit it.

A finding of this rule points at `packages.lock.json`.
