# release/reproducible-build/maven

Release builds are reproducible

Implements [release/reproducible-build](release--reproducible-build.md) for the `maven` artifact: it runs when the release publishes one (see [artifacts](capabilities.md#artifacts)).

## Requirement

The published archives are reproducible: Maven sets `project.build.outputTimestamp`; Gradle sets `preserveFileTimestamps = false` and `reproducibleFileOrder = true` on its archive tasks, or the wrapper is Gradle 9 or later, where that is the default; or `SOURCE_DATE_EPOCH` is set for the release build.

## Why

When anyone can rebuild a release bit for bit from the tag, a tampered artifact or a compromised build machine shows up as a mismatch.

## Capability applies when

```cel
release.exists || repo.artifacts.size() > 0
```

## Fix

Maven: set `<project.build.outputTimestamp>` (the release plugin updates it); Gradle: configure `tasks.withType<AbstractArchiveTask>` or update to Gradle 9.

Agent instruction: Add the stack's reproducibility settings to the release build and derive SOURCE_DATE_EPOCH from `git log -1 --format=%ct`; do not change what is built.

A finding of this rule points at the file `(["pom.xml", "build.gradle.kts", "build.gradle"].filter(f, file(f)) + ["pom.xml"])[0]` yields.
