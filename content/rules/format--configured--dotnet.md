## Requirement

`dotnet format` or CSharpier runs in a hook, the task runner or CI, or the code style is configured (C# style rules in .editorconfig, or a CSharpier configuration) in the project or a parent directory. Another formatter is added with `accept:`.

## Why

Without one formatter every editor reformats differently and diffs fill with whitespace churn that hides the real change.

## Fix

Add `dotnet format --verify-no-changes` to the lint target and a hook; keep the style rules in .editorconfig.

Agent instruction: Add `dotnet format --verify-no-changes` to the lint target and the dotnet-format hook, with code style rules in .editorconfig; reformat in a separate commit.
