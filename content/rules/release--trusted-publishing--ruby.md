Packages are published with trusted publishing

## Requirement

A tag-triggered GitHub or GitLab workflow that publishes to RubyGems (`gem push`, rubygems/release-gem) uses trusted publishing: `id-token: write` and no GEM_HOST_API_KEY or `--token` from secrets; on GitLab `id_tokens:`.

## Why

A registry token in CI secrets is valid for months and publishes from anywhere once leaked; an OIDC token is minted per run, scoped to this repository and workflow, and expires in minutes.

## Applies when

```cel
tagged_workflows().filter(w, ci_kind(w) in ["github", "gitlab"] && steps(w).exists(s,
  s.uses.startsWith("rubygems/release-gem")
  || s.run.matches("\\b(gem push)\\b"))).size() > 0
```

## Check

For each `item` in:

```cel
tagged_workflows().filter(w, ci_kind(w) in ["github", "gitlab"] && steps(w).exists(s,
  s.uses.startsWith("rubygems/release-gem")
  || s.run.matches("\\b(gem push)\\b")))
```

```cel
ci_kind(item) == "gitlab"
  ? text(item).matches("(?m)^\\s*id_tokens:")
  : text(item).matches("id-token:\\s*write")
    && !grep(item, r'^\s*-?\s*(?:GEM_HOST_API_KEY)\s*:\s*["\x27]?\$\{\{\s*secrets\.(\w+)').exists(m, m.match.upperAscii() != "GITHUB_TOKEN")
    && !grep(item, r'--token[\s=]+["\x27]?\$\{\{\s*secrets\.(\w+)').exists(m, m.match.upperAscii() != "GITHUB_TOKEN")
```

## Fix

Register the workflow as a trusted publisher on rubygems.org, release with rubygems/release-gem from a job with `id-token: write`, and delete the API key secret.

Agent instruction: Grant `id-token: write` on the publishing job, remove the registry token from env/with (pypa/gh-action-pypi-publish without password, `npm publish` with npm 11.5.1 or newer, rust-lang/crates-io-auth-action for cargo, rubygems/release-gem for gems; on GitLab add `id_tokens:` with the registry's audience), and tell the user to register the trusted publisher and delete the secret.
