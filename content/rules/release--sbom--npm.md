# release/sbom/npm

Releases publish an SBOM

Implements [release/sbom](release--sbom.md) for the `npm` artifact: it runs when the release publishes one (see [artifacts](capabilities.md#artifacts)).

## Requirement

npm resolves a package's dependencies from its manifest and lockfile; the registry holds the graph, so a separate SBOM adds nothing unless the package bundles dependencies (then `npm sbom` with the files uploaded as release files).

## Why

Consumers and scanners need to know what is inside an artifact; generating the SBOM in the pipeline ties it to the exact build.

## Fix

Run the artifact's SBOM producer in the release workflow (`fleetlint explain release/sbom/<artifact>`): syft or GoReleaser `sboms:` for release files, BuildKit `sbom: true` or `cosign attest --type spdx` for an image, the CycloneDX build plugin for Maven, NuGet and Android; upload the files with the release.

Agent instruction: In the tag-triggered release workflow add a step producing an SPDX JSON SBOM for each published artifact (syft for files, BuildKit `sbom: true` for images, the stack's CycloneDX plugin otherwise) and include the files in the release upload step. Do not change other steps. If the repo uses GoReleaser, add a `sboms:` section instead.
