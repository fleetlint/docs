# release/sbom/maven

Releases publish an SBOM

Implements [release/sbom](release--sbom.md) for the `maven` artifact: it runs when the release publishes one (see [artifacts](capabilities.md#artifacts)).

## Requirement

The release runs the CycloneDX Gradle plugin's `cyclonedxBom` task or the cyclonedx-maven-plugin (`makeBom`/`makeAggregateBom`), which read the build's resolved dependencies, and publishes the BOM as an extra artifact (the `cyclonedx` classifier on Maven Central).

## Why

Consumers and scanners need to know what is inside an artifact; generating the SBOM in the pipeline ties it to the exact build.

## Capability applies when

```cel
release.exists || repo.artifacts.size() > 0
```

## Fix

Apply the CycloneDX Gradle plugin (`org.cyclonedx.bom`) and run `./gradlew cyclonedxBom` in the release workflow (or bind cyclonedx-maven-plugin's makeAggregateBom); publish the BOM with the artifact.

Agent instruction: In the tag-triggered release workflow add a step producing an SPDX JSON SBOM for each published artifact (syft for files, BuildKit `sbom: true` for images, the stack's CycloneDX plugin otherwise) and include the files in the release upload step. Do not change other steps. If the repo uses GoReleaser, add a `sboms:` section instead.

See: <https://fleetlint.org/baseline/#releases>, <https://github.com/CycloneDX/cyclonedx-maven-plugin>
