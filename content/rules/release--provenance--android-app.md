# release/provenance/android-app

Releases attest build provenance

Implements [release/provenance](release--provenance.md) for the `android-app` artifact: it runs when the release publishes one (see [artifacts](capabilities.md#artifacts)).

## Requirement

The workflow that publishes the APK or AAB attests its provenance: actions/attest-build-provenance (the subject path covering the files), the SLSA generator, `cosign attest-blob`, or GitLab's artifact provenance (`RUNNER_GENERATE_ARTIFACTS_METADATA: "true"`).

## Why

Provenance ties the artifact to the exact source and workflow that built it, which a signature alone does not.

## Capability applies when

```cel
release.exists || repo.artifacts.size() > 0
```

## Fix

Add actions/attest-build-provenance with `subject-path` covering the APK or AAB (GitHub), `RUNNER_GENERATE_ARTIFACTS_METADATA: "true"` (GitLab) or `cosign attest-blob --predicate` (Gitea) to the release workflow.

Agent instruction: Add a step `uses: actions/attest-build-provenance` with `subject-path` covering the release files (or `subject-name` and `subject-digest` for an image, with `push-to-registry: true`); grant `id-token: write` and `attestations: write` to that job only. On GitLab set the variable RUNNER_GENERATE_ARTIFACTS_METADATA to "true" on the release job. On Gitea write a SLSA v1 predicate and run `cosign attest-blob --type slsaprovenance1`.
