## Commands

### fleetlint

Policy for a fleet of repositories.

```text
fleetlint [command]
```

fleetlint checks how a repository is set up (hooks, task runner, lint config, CI, release) against a catalog of rules, and tells you how to fix the gaps.

| Flag | Default | Description |
|---|---|---|
| `--version` |  | print the version |

### fleetlint baseline

Grandfather the current findings so only new ones fail (the file may only shrink afterwards).

```text
fleetlint baseline [flags]
```

baseline writes .fleetlint-baseline.json (or the path in .fleetlint.yaml) with a fingerprint of every current finding. Findings in the file are reported as baselined instead of failing. Re-running removes entries that no longer match and never adds new ones, so the debt can only go down; `--reset` starts over.

| Flag | Default | Description |
|---|---|---|
| `--reset` |  | grandfather everything currently failing, including findings newer than the existing baseline |

### fleetlint docs

Generate the rule, CEL and CLI reference pages (or verify they are current with `--check`).

```text

```

docs writes a page per rule of the built-in presets, the capability matrix, the CEL reference and the CLI reference into `--out`, and removes the pages it generated earlier that it no longer generates, such as those of a removed rule. Pages it did not generate are left alone.

| Flag | Default | Description |

### fleetlint fix

Show (or with `--apply`, perform) the mechanical fixes for failing rules.

```text
fleetlint fix [rule-id...] [flags]
```

fix plans the declarative actions attached to failing rules: creating files from templates, untracking files, adding .gitignore patterns. It never overwrites an existing file. Without `--apply` it only prints what it would do, and `--apply` writes only into a clean working tree unless `--allow-dirty` is given. Rules without actions print their instruction instead.

`--apply --pr` leaves the working tree alone: it fixes the default branch in a temporary worktree, commits on fleetlint/fixes, force-pushes that branch and opens or updates its pull request, through the forge's API with `--token` (`FLEETLINT_TOKEN`), `GITHUB_TOKEN`, `GITEA_TOKEN` or `GITLAB_TOKEN`, else with gh, tea or glab. `--forge` (`FLEETLINT_FORGE`) names a self-hosted forge or its kind; in GitHub, Gitea, Forgejo or GitLab CI the job's own server is known.

| Flag | Default | Description |
|---|---|---|
| `--allow-dirty` |  | with `--apply`: write although the working tree has uncommitted changes |
| `--apply` |  | write the changes (default is a dry run) |
| `--forge string` |  | the forge to use: github, github:&lt;host&gt;, gitea:&lt;host&gt;, gitlab:&lt;host&gt; or an https URL (default `$FLEETLINT_FORGE`) |
| `--pr` |  | with `--apply`: commit the fixes of the default branch on fleetlint/fixes and open a pull request |
| `--token string` |  | token for that forge's API and for pushing (default `$FLEETLINT_TOKEN`, which keeps it out of the process list) |

### fleetlint fleet

Check many repositories and write one report (matrix, per-repo tasks, history).

```text
fleetlint fleet [path...] [flags]
```

fleet reads a fleet file (`--repos`) and/or repository paths given as arguments, runs check in each, and writes fleet.html, fleet.md, fleet.json, actions/&lt;repo&gt;.md and history/&lt;timestamp&gt;.json into `--out`. URL entries are cloned into `--cache`, else the fleet file's cache:, else the user cache directory (fleetlint/repos). `--from` lists an owner's repositories through the forge API (`GITHUB_TOKEN`, `GITEA_TOKEN` or `GITLAB_TOKEN` from the environment, if set) and clones them over https with the same token; without one, public repositories only. `--discover` walks a directory for git repositories (groups follow the directory layout) and lists project directories that are in no repository of their own. `--fix` plans the mechanical fixes (fleetlint fix) in every local repository (a dry run, kept out of history/); with `--apply` it writes them, into clean working trees only unless `--allow-dirty` is given, and the report shows the state after them. Nothing is committed. `--fix --apply --pr` proposes the fixes instead, as a pull request per repository from fleetlint/fixes, clones included (fleetlint fix `--apply --pr`). `--deep` runs rules that execute repository code in the local repositories; clones (url entries, `--from`) run that code only with `--deep-clones`.

| Flag | Default | Description |
|---|---|---|
| `--allow-dirty` |  | with `--fix --apply`: write into working trees that have uncommitted changes |
| `--apply` |  | with `--fix`: write the changes; nothing is committed |
| `--cache string` |  | directory for cloned url entries (overrides the fleet file; default: the user cache directory) |
| `--deep` |  | also run rules that execute repository code (local repositories only) |
| `--deep-clones` |  | with `--deep`: also execute the code of cloned repositories (url entries, `--from`), which you may not control |
| `--discover stringArray` |  | find git repositories under a directory, up to 4 levels down (repeatable) |
| `--exclude stringArray` |  | with `--discover`: skip paths matching this glob, relative to the directory (e.g. '\*/third\_party/\*'; repeatable) |
| `--fail` |  | exit 1 if any repository has errors |
| `--fix` |  | plan the mechanical fixes in every local repository (dry run) |
| `--forge string` |  | the forge to use: github, github:&lt;host&gt;, gitea:&lt;host&gt;, gitlab:&lt;host&gt; or an https URL (default `$FLEETLINT_FORGE`) |
| `--from stringArray` |  | discover repositories on a forge: github:&lt;owner&gt;, gitea:&lt;host&gt;/&lt;owner&gt; or gitlab:&lt;host&gt;/&lt;group&gt; with its subgroups (repeatable; archived repositories and forks are skipped) |
| `--jobs int` | `4` | check this many repositories at once |
| `--keep-history int` |  | keep only the latest N runs in history/ (0 keeps all) |
| `--out string` | `fleet-report` | output directory |
| `--pr` |  | with `--fix --apply`: propose each repository's fixes as a pull request from fleetlint/fixes (clones too) instead of writing working trees |
| `--repos string` |  | fleet file (version, cache, include, defaults, groups, repos: [{path\|url, name, team, group, tier, visibility}]) |
| `--rule stringArray` |  | with `--fix`: only fix this rule (repeatable) |
| `--token string` |  | token for that forge's API and for pushing (default `$FLEETLINT_TOKEN`, which keeps it out of the process list) |
| `--update` |  | git pull cached clones before checking |

### fleetlint hierarchy

Print the catalogs in the order they apply, with their pins.

```text
fleetlint hierarchy [flags]
```

Lists every catalog of the run in the order it applied: how it was referenced, its label, what it calls itself, the digest or artifact that pins its content, what it builds on and what it contributed. A later catalog adjusts an earlier one within the earlier one's policy, so the order is the precedence.

| Flag | Default | Description |
|---|---|---|
| `-f, --format string` | `table` | output format: table, json, markdown |

## Exit codes

| Code | Meaning |
|---|---|
| `0` | `check` found nothing at or above `--fail-on`; any other command finished. |
| `1` | `check` found a failing rule at or above `--fail-on` (default `error`), or a rule could not be evaluated, whatever `--fail-on` says. `fleet --fail`: a repository has error findings or rule errors, or could not be checked. |
| `2` | Configuration or usage error: an invalid `.fleetlint.yaml` or catalog, a catalog that cannot be fetched, a catalog `--require` names that the configuration lacks, a path that is not a repository, an unknown flag or wrong arguments, `fix --apply` in a working tree with uncommitted changes (with `--pr`: no remote, or a default branch whose configuration fails in one of these ways), pages that differ under `docs --check`. |
| `3` | Any other error: a push or pull request that failed, a git command that failed, output that could not be written. |

## Environment variables

| Variable | Effect |
|---|---|
| `FLEETLINT_TOKEN` | Default for `--token` (`fix --apply --pr`, `init --pr`, `fleet`): the token for the forge's API and for pushing. Keeps the token out of the process list. |
| `FLEETLINT_FORGE` | Default for `--forge`: `github`, `github:<host>`, `gitea:<host>`, `gitlab:<host>` or an https URL, for a self-hosted forge. |
| `FLEETLINT_CACHE_DIR` | Directory for pinned catalogs (in `catalogs/` below it) instead of the user cache directory; CI sets it to keep the cache between runs. |
| `NO_COLOR` | Any value turns colored output off unless `--color` is given. |
| `GITHUB_TOKEN`, `GH_TOKEN` | Token for GitHub (`GH_TOKEN` when `GITHUB_TOKEN` is unset): repository visibility, `fleet --from github:`, pull requests. In a Gitea or Forgejo Actions run, `GITHUB_TOKEN` is also the token for that instance when `GITEA_TOKEN` is unset. |
| `GITEA_TOKEN` | Token for a Gitea or Forgejo host fleetlint may contact. |
| `GITLAB_TOKEN` | Token for a GitLab host fleetlint may contact. |
| `GITEA_HOST`, `GITLAB_HOST` | Comma-separated self-hosted Gitea, Forgejo or GitLab hosts fleetlint may contact and send their token to. Not needed for gitlab.com, a host named by `--forge` or `--from`, the remote of a `--pr`, or the instance running the CI job. |
| `GITHUB_API_URL` | Set by GitHub Actions: on GitHub Enterprise Server, the API fleetlint uses for GitHub. In Gitea and Forgejo Actions, the API of that instance. |
| `GITHUB_ACTIONS` | Set by GitHub Actions: with `GITHUB_SERVER_URL`, the GitHub Enterprise Server running the job, which fleetlint then treats as a known GitHub host. |
| `GITEA_ACTIONS`, `FORGEJO_ACTIONS`, `GITHUB_SERVER_URL` | Set by Gitea and Forgejo Actions: the instance running the job, which fleetlint then treats as a known Gitea host. |
| `GITLAB_CI`, `CI_SERVER_HOST`, `CI_API_V4_URL` | Set by GitLab CI: the instance running the job and its API, which fleetlint then treats as a known GitLab host. |
| `FLEETLINT_VERIFY` | Read by the install script, not by `fleetlint`: `cosign` makes `install.sh` fail unless cosign is installed and verifies the signature of the release's `checksums.txt` (`curl … \| FLEETLINT_VERIFY=cosign sh`). |
