Dependency lockfile is committed

## Requirement

Cargo.lock is tracked when Cargo.toml declares dependencies or a workspace; a workspace member uses the Cargo.lock of the workspace root above it.

## Why

Builds are reproducible only when dependency versions are pinned in git.

## Check

```cel
"Cargo.lock" in tracked() || ["../", "../../", "../../../"].exists(d, file(d + "Cargo.lock") && file(d + "Cargo.toml") && text(d + "Cargo.toml").matches(r'(?m)^\[workspace\]')) || !text("Cargo.toml").matches(r'\[((workspace\.)?(dev-|build-)?dependencies|workspace)\]')
```

## Fix

Run `cargo generate-lockfile` and commit Cargo.lock.

Agent instruction: Run the package manager to produce the lockfile, remove any .gitignore entry for it, and commit it.

A finding of this rule points at `Cargo.lock`.
