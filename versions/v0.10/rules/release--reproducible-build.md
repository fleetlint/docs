# release/reproducible-build

Release builds are reproducible

A capability keyed by published artifact: each kind the release publishes is checked by its own implementation, and every one must pass. ## Requirement

The release build removes what differs between two builds of the same commit: local paths and timestamps. The stack's build settings do it for the artifact, or `SOURCE_DATE_EPOCH` is set for the release build (in the workflow that publishes the artifact or in the task runner). Each artifact kind's implementation says what counts for it.

## Why

When anyone can rebuild a release bit for bit from the tag, a tampered artifact or a compromised build machine shows up as a mismatch.

## Applies when

```cel
release.exists || repo.artifacts.size() > 0
```

## Fix

Set the stack's reproducibility options in the release build (see https://reproducible-builds.org/docs/) and export SOURCE_DATE_EPOCH from the commit time.

Agent instruction: Add the stack's reproducibility settings to the release build and derive SOURCE_DATE_EPOCH from `git log -1 --format=%ct`; do not change what is built.
