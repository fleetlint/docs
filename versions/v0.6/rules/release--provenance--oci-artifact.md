# release/provenance/oci-artifact

Releases attest build provenance

Implements [release/provenance](release--provenance.md) for the `oci-artifact` artifact: it runs when the release publishes one (see [artifacts](capabilities.md#artifacts)).

## Requirement

Provenance is attached to the artifact digest: actions/attest-build-provenance with `subject-digest` and `push-to-registry: true`, `cosign attest --type slsaprovenance`, or the SLSA generic generator over the digest.

## Why

Provenance ties the artifact to the exact source and workflow that built it, which a signature alone does not.

## Capability applies when

```cel
release.exists || repo.artifacts.size() > 0
```

## Fix

After the push step add actions/attest-build-provenance with `subject-name: <registry>/<repository>`, `subject-digest: <digest>` and `push-to-registry: true`; the job needs `id-token: write` and `attestations: write`.

Agent instruction: Add actions/attest-build-provenance after the push step with `subject-name`, `subject-digest` from the push step's output and `push-to-registry: true`; grant `id-token: write`, `attestations: write` and `packages: write` to that job only.

See: <https://fleetlint.org/baseline/#releases>, <https://slsa.dev/spec/v1.0/provenance>, <https://docs.github.com/en/actions/security-for-github-actions/using-artifact-attestations/using-artifact-attestations-to-establish-provenance-for-builds>
