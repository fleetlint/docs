# Capabilities

Generated by `fleetlint docs`; do not edit. A capability states a requirement; each stack implements it with its own tools (`rules/<family>/<name>/<stack>.yaml`). `any` is the stack-neutral implementation: it checks stacks without their own and repositories where no stack is detected, and its satisfiers count for every stack. *Combine* says how the implementations add up: `all`, every implementation that runs must pass; `any`, one passing is enough (for what belongs to the repository rather than to each stack). `n/a` means the requirement does not apply to the stack (its page says why). A dash means no implementation yet; a report says so for a repository with that stack.

## Artifacts

A capability keyed by artifact (`by: artifact`) is checked once per artifact kind the release publishes, with an implementation per kind (`rules/<family>/<name>/<artifact>.yaml`): a repository that publishes binaries and an npm package must satisfy both, and the report names the one that does not. There is no `any` implementation here: what counts as signed, attested or described differs per kind. `n/a` means the requirement does not apply to the kind (its page says why). Kinds are detected from the workflows that publish them, by the catalog's `artifacts/<kind>.yaml`; a repository pins `facts: {artifacts: [...]}` when detection misses one.
